Backpropagation — Cleared Up

Two specific doubts resolved, strict naming enforced throughout, full numeric walkthrough on a 2→2→1 network.

01 Why do activations have gradients? Only weights and biases get updated.

?
Your Confusion

I thought only weights and biases get changed. So why is there a ∂L/∂a? What is the gradient of an activation even for?

✓
The Answer

You are completely correct — only w and b are ever updated. Activations are computed during the forward pass and then fixed. They are never changed by gradient descent.

But to compute ∂L/∂w — which IS what we need — the chain rule forces us to pass through ∂L/∂a first, because the activation sits between the weight and the loss in the dependency chain. ∂L/∂a is a mathematical stepping stone, not a target.

⬡
Analogy — The Blame Chain

A factory line: Machine settings → Worker output → Final product. The product is defective. You want to know how much to adjust the machine settings (= weights). You cannot reach the machine directly — you first measure how much the worker's output (= activation) contributed to the defect. That intermediate blame score is ∂L/∂a. It is a relay baton, not a destination. You never fix the worker's output directly. You fix the machine that produced it.

Gradient Computation

  • Computes ∂L/∂a at every activation
  • Computes ∂L/∂z at every pre-activation
  • Computes ∂L/∂w and ∂L/∂b
  • This is just measuring slopes
  • Nothing is changed at this stage

Parameter Update

  • Updates only w and b
  • Uses the gradients from the left column
  • Rule: w ← w − α · ∂L/∂w
  • Activations are never touched
  • They will naturally improve next forward pass

✓ Gets Updated — Learnable Parameters

  • w[l]ᵢⱼ — all weights in all layers
  • b[l]ⱼ — all biases in all layers

Not Updated — Computed Values

  • z[l]ⱼ — pre-activations (weighted sums)
  • a[l]ⱼ — activations (after σ)
  • Their gradients are relay batons only

02 Strict, Consistent Naming Convention

!
The Problem

The previous file mixed a₁, h₁, z_out, ŷ, and flat-numbered w₁…w₆ — with no indication of which layer a weight belongs to. One rule is enforced below, everywhere, without exception.

SymbolRead asMeaningRole
xᵢ x sub i The i-th input. Equivalently written a[0]ᵢ — layer 0 activation. Data
w[l]ⱼᵢ w, layer l, to-j from-i Weight in layer l. Connects neuron i (previous layer) to neuron j (this layer). Subscript order: destination first. Updated
b[l]ⱼ b, layer l, neuron j Bias of neuron j in layer l. Updated
z[l]ⱼ z, layer l, neuron j Pre-activation. The raw weighted sum before σ is applied. z = Σ(w·a) + b. The neuron has "computed" but not yet "fired". Computed
a[l]ⱼ a, layer l, neuron j Post-activation. After applying σ. a = σ(z). This is what leaves the neuron and travels forward. Computed
a[L]₁ = ŷ final layer activation The network's prediction. Same symbol system — just the last layer. Not a special symbol. Computed
L script-L, "the loss" A single scalar measuring how wrong the prediction is. All of backprop computes gradients of L. Target to minimise
∂L/∂a[l]ⱼ gradient of loss w.r.t. activation The relay baton. Computed en-route backwards. Used only to find the next gradient further back. Never used to update anything. Messenger
∂L/∂w[l]ⱼᵢ gradient of loss w.r.t. weight The final destination of backprop. Gradient descent subtracts a scaled version of this from the weight. Used to update w

03 The Network — 2 Inputs → 2 Hidden → 1 Output

Every symbol below follows the table above exactly. Forward pass in blue. Gradient flow (backward) in red dashed. Weights that get updated are labeled in purple.

04 Forward Pass — Real Numbers, Strict Names

Setup: x₁ = 0.5, x₂ = 0.8, y = 1, all weights = 0.5, all biases = 0, activation = sigmoid.

F1
Compute z¹₁ and z¹₂ — pre-activations of hidden layer
z¹₁ = w¹₁₁·x₁ + w¹₁₂·x₂ + b¹₁ = 0.5×0.5 + 0.5×0.8 + 0 = 0.65
z¹₂ = w¹₂₁·x₁ + w¹₂₂·x₂ + b¹₂ = 0.5×0.5 + 0.5×0.8 + 0 = 0.65

z is nothing more than a weighted sum. The neuron has received its inputs but has not yet "activated".

F2
Apply σ to get a¹₁ and a¹₂ — post-activations
a¹₁ = σ(z¹₁) = σ(0.65) = 1 / (1 + e^{−0.65}) ≈ 0.657
a¹₂ = σ(z¹₂) ≈ 0.657

a¹₁ means "activation of neuron 1 in layer 1". This is what leaves the neuron and travels to the next layer.

F3
Compute z² — pre-activation of output neuron
z² = w²₁₁·a¹₁ + w²₁₂·a¹₂ + b² = 0.5×0.657 + 0.5×0.657 + 0 = 0.657
F4
Output prediction — a²₁ = ŷ
a²₁ = ŷ = σ(z²) = σ(0.657) ≈ 0.659
F5
Compute loss 𝓛 = (ŷ − y)²
𝓛 = (0.659 − 1)² = (−0.341)² ≈ 0.116

Forward pass complete. Now backprop determines how every weight contributed to this 0.116.

05 Backward Pass — Gradient Chain, Step by Step

We work right to left. At each step a gradient is computed. Activation gradients are computed solely to enable the next step — they update nothing.

B1 — Gradient w.r.t. the output activation

∂𝓛/∂a²₁ = 2·(ŷ − y) = 2·(0.659 − 1) = −0.682
∂𝓛/∂a²₁ = −0.682 Messenger entering from the loss. a²₁ is not updated.

B2 — Differentiate through the output activation function

∂𝓛/∂z² = (∂𝓛/∂a²₁) · σ'(z²) = −0.682 × [0.659 × (1 − 0.659)] = −0.682 × 0.225 ≈ −0.153
∂𝓛/∂z² = −0.153 Still a messenger. z² is not updated either.

B3 — Gradient w.r.t. output weights w²₁₁ and w²₁₂ — these get updated

∂𝓛/∂w²₁₁ = (∂𝓛/∂z²) · a¹₁ = −0.153 × 0.657 ≈ −0.101
∂𝓛/∂w²₁₂ = (∂𝓛/∂z²) · a¹₂ ≈ −0.101
Gradient Descent Update (α = 0.1)
w²₁₁ ← w²₁₁ − α·(∂𝓛/∂w²₁₁)0.5 − 0.1×(−0.101) = 0.5101
w²₁₂ ← w²₁₂ − α·(∂𝓛/∂w²₁₂)0.5 − 0.1×(−0.101) = 0.5101

B4 — Propagate gradient back to hidden activations a¹₁ and a¹₂

∂𝓛/∂a¹₁ = (∂𝓛/∂z²) · w²₁₁ = −0.153 × 0.5 = −0.077
∂𝓛/∂a¹₂ = (∂𝓛/∂z²) · w²₁₂ = −0.153 × 0.5 = −0.077
⬡
This is exactly where your confusion was

We just computed ∂𝓛/∂a¹₁ = −0.077. We will never use this to update a¹₁. We computed it because the next step needs it to reach ∂𝓛/∂z¹₁, which then reaches ∂𝓛/∂w¹₁₁ — the weight gradient we actually care about. The activation gradient exists for one reason only: it is a required intermediate in the chain rule.

B5 — Through the hidden activation function

∂𝓛/∂z¹₁ = (∂𝓛/∂a¹₁) · σ'(z¹₁) = −0.077 × [0.657 × (1−0.657)] = −0.077 × 0.225 ≈ −0.0174
∂𝓛/∂z¹₂ ≈ −0.0174 (symmetric)

B6 — Gradient w.r.t. input-layer weights — these get updated

∂𝓛/∂w¹₁₁ = (∂𝓛/∂z¹₁) · x₁ = −0.0174 × 0.5 = −0.0087
∂𝓛/∂w¹₁₂ = (∂𝓛/∂z¹₁) · x₂ = −0.0174 × 0.8 = −0.0139
Gradient Descent Update (α = 0.1)
w¹₁₁ ← 0.5 − 0.1×(−0.0087)= 0.5009
w¹₁₂ ← 0.5 − 0.1×(−0.0139)= 0.5014

07 The One Rule to Internalise

◈
The Golden Rule of Backprop

Backprop computes ∂𝓛/∂(everything) — weights, biases, activations, pre-activations. But only ∂𝓛/∂w and ∂𝓛/∂b are used to change anything. All other gradients are mathematically required relay points demanded by the chain rule. They carry blame backwards, neuron by neuron, until it reaches a learnable parameter — and only then is something updated.

Why does PyTorch compute .grad for activations at all?

When you call loss.backward(), PyTorch accumulates ∂𝓛/∂tensor for every tensor with requires_grad=True. For parameters (weights, biases), the optimizer reads .grad and updates them. For intermediate activations, PyTorch discards their gradients after the backward pass by default — unless you call tensor.retain_grad() explicitly. This is the library itself confirming that activation gradients are temporary messengers, not final destinations.

✓
Intuition Check

If ∂𝓛/∂a¹₁ = −0.077, it means: if a¹₁ increased by 1, the loss would decrease by 0.077. Can you directly increase a¹₁? No — it is just σ(z¹₁), a computed output. What you can do is increase the weights w¹₁₁ and w¹₁₂ that control z¹₁, which will naturally push a¹₁ higher on the next forward pass. That is exactly what backprop does.
